One skill for now: **review**. There is no build skill — to write a new schema or query, the
trees in [Drizzle ORM](../../knowledge-base/drizzle-orm.md) § 5 are consulted directly.

## What the package added

The skill described **four** probes in a table. The script runs eleven: the original four plus
seven the scan asked for and did not have a command for.

| Extra probe | Rule |
| --- | --- |
| a query inside `map`/`for` | `DRZ-RQB-01` — the most common finding and the most expensive |
| `update`/`delete` without `where` | `DRZ-QUERY-04` — blocking, and one line produces it |
| `sql\`\`` with interpolation | `DRZ-QUERY-03` — becomes **security** when the value comes from the user |
| external `db` inside a `transaction` | `DRZ-TX-03` — the write leaves the transaction with no error |
| `push` outside local | `DRZ-MIG-02`, `DRZ-MIG-04` |
| `.default` with a computed value | `DRZ-SCHEMA-04` — the value freezes in the migration's SQL |
| hand-written Zod | `DRZ-ZOD-01` |

**Probe S1 remains the mandatory stop:** the script prints **both lists** — what is exported as
`pgTable`/`relations` and what is registered in `drizzle({ schema })` — and the comparison is the
reviewer's. With the relational API switched off, every hand-built read is a **consequence**, and
criticizing each one is noise.

## The ID map

Generated by `scripts/gerar-mapa-de-ids.sh`: **32 IDs**, with the **"body in satellite"** column,
because `DRZ-CORE-*` is declared only in the hub. `DRZ-SCHEMA-01` is an alias of `DRZ-CORE-02` and
does not appear in a review.

**The rows without an ID are deliberate.** A redundant index, a range filter without an index, an
expression over a column and an unbounded listing have **no `DRZ-*`** — the grid cites the
normative note, and inventing an ID there would be worse than not citing.

```bash
bash plugins/tc96-backend/skills/drizzle-review/scripts/gerar-mapa-de-ids.sh
bash scripts/instalar.sh
```
