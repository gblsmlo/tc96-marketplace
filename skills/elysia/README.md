## What the packages added

| Skill | Gained | Gap it closed |
| --- | --- | --- |
| `elysia-diagnose` | **`scripts/sondas.sh`** — ten lifecycle probes | the skill had "the probes" as a section **with no command**: only the scope test in TypeScript |
| `elysia-build` · `elysia-schema` | `scripts/autoverificar.sh` | the 15- and 14-item checklists were reading |

**The probe that existed nowhere: diagnose's S1.** It measures **registration order by line
number** — a hook registered after the file's first route (`ELYSIA-CORE-01`), which is the first
hypothesis, always, and raises neither error nor warning.

**And what the probe deliberately does not do:** prove scope. `local` and `scoped` produce the
same code inside the plugin; the difference only appears in the consuming instance. The proof is
the test in `references/prova-de-escopo.md` — and the table there shows why the test most
projects have (inside the plugin) **passes in both cases**.

## The ID map

Generated by `elysia-diagnose/scripts/gerar-mapa-de-ids.sh`, the same in all three. **44 IDs** —
the number the hub declares, which serves as the check. Because `ELYSIA-APP-*` is declared only in
the hub, the map has a **"body in satellite"** column, and the 9 `APP` rows appear explicitly as
"hub only" — matching the docs' count.

**The family's quirk:** the aliases are **partial**. `ELYSIA-APP-03` is an alias of
`ELYSIA-CORE-02` **only** in the destructuring clause; `ELYSIA-TYPE-11` is an alias of
`ELYSIA-APP-04` **only** in the `strict` one. Outside those clauses, both are citable for what is
theirs alone — and that is why the map's header carries the whole of § 6.2.

```bash
bash plugins/hermes-backend/skills/elysia-diagnose/scripts/gerar-mapa-de-ids.sh
bash scripts/instalar.sh
```
