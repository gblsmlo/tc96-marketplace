## What the packages added

All four skills described `curl` probes **in a table**. Now they run:

| Script | What it does |
| --- | --- |
| `http-review/scripts/sondas.sh <base> <route> [write] [origin]` | S1–S8, including a stale `If-Match` and a refused origin |
| `http-diagnose/scripts/sondas-cors.sh <url> [origin]` | all five, with the **reading** of each result |
| `http-cache/scripts/sondas-cache.sh <url> [write]` | extracts the real `ETag` and **reuses** it in `If-None-Match` |
| `http-contract/scripts/conferir.sh <base> <route> [write]` | `GET`/`HEAD`/`PATCH`/`POST`/error, and lists what requires reading |

**Two probes were designed to catch what nobody runs:**

- **a refused origin** (`curl -H 'Origin: https://malicious.example'`) — if the origin is
 echoed, it is blind reflection (`HTTP-CORS-01`); if `Vary: Origin` is missing, the cache serves
 one origin's response to another (`HTTP-CORS-03`);
- **a write with a stale `If-Match`** — if it is **applied**, there is silent data loss under
 concurrency (`HTTP-CACHE-08`). It is the family's gravest finding, and the least tested.

`curl` **does not do CORS** — and that is exactly why it helps: it shows what the server
answers, without the browser in the way.

## The ID map

Generated by `http-review/scripts/gerar-mapa-de-ids.sh`, the same across all four. **74 IDs** —
the number the hub declares, with continuous numbering: a missing ID is a structural bug.

**The quirk:** `Vary` has **three** rules that **are not aliases** — `HTTP-CACHE-10`
(caching), `HTTP-NEG-01` (compression) and `HTTP-CORS-03` (dynamic origin), on top of the general
statement `HTTP-CORE-04`. Each adds a concrete obligation, and citing the generic one where the
specific one fits loses information. The map's header carries the whole of § 6.2.

```bash
bash plugins/hermes-core/skills/http-review/scripts/gerar-mapa-de-ids.sh
bash scripts/instalar.sh
```
