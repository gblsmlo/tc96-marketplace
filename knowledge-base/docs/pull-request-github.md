### Antes de criar o PR

- **Revise suas próprias mudanças** antes de solicitar revisão
- **Mantenha PRs pequenos e focados** - prefira múltiplos PRs menores a um gigante
- **Atualize sua branch** com a base principal antes de criar o PR
- **Teste locally** todas as alterações

### Ao criar o PR

- **Título claro e descritivo**: Ex: "feat: adicionar validação de email no formulário de cadastro"
- **Descrição completa**: Use o [Pull Request Template](pull-request-template.md) para padronizar
- **Link com issues**: Use keywords como "Closes #123" ou "Fixes #456"
- **screenshots/gifs**: Para mudanças visuais, adicione evidências

### Durante a revisão

- **Responda todos os comentários** - mesmo um "feito" é importante
- **Não take comentários como pessoais** - revisão é sobre o código
- **Explique suas escolhas** quando necessário
- **Solicite clarification** se algum comentário não estiver claro

### Após aprovação
- **Squash commits** se apropriado
- **Delete a branch** após o merge
- **Celebre** sua contribuição

## Template
Para facilitar a criação de PRs, utilize o [Pull Request Template](pull-request-template.md) disponível neste vault.
